## 2. 设备产品与 32 个数据点

已记录的静态配置属于 **1271W** 产品，共 **32 个数据点（索引 0–31）**。MQTT 解码器按产品配置处理位宽：
- 索引 0–14 为位字段，位宽依次为 `1×11, 2, 1, 3, 2`。
- 索引 15–31 为字节字段，长度依次为 `1×9, 2×6, 17, 1` 字节。

当前保存资料中有明确字段名或真机对照用途的索引：

| DP 索引 | 字段名 | 已知含义 | 证据/单位 |
|---:|---|---|---|
| 3 | `self_cleaning` | 自清洁状态 | App/API 与设备上报字段对照 |
| 4 | `quantitative_fit` | 定量适配/定量出水校准状态 | 字段名来自设备数据点映射；具体全部状态枚举未保留 |
| 7 | `detect_status` | 出水检测状态；1 开始、0 结束用于配对一次出水 | 真机 MQTT 上报验证 |
| 13 | `function_status` | 功能状态 | App/API 与设备上报字段对照 |
| 18 | `new_bottles` | 标记流程新分配/候选奶瓶编号 | 真机上报验证；候选编号不等于已写入永久列表 |
| 21 | `bottle_tag` | 奶瓶标记/称重流程控制状态 | 真机验证：0 结束/清理流程，1 空托盘去皮，2 放瓶取重 |
| 22 | `bottle_record` | 出水记录关联的奶瓶编号 | 与备奶记录对照 |
| 25 | `record` | 本次备奶/出水量 | 单位 mL，备奶量不是实际喝入量 |
| 26 | `wateryield` | 设备当前出水设定 | 单位 mL |
| 27 | `bottle_weight` | 标记流程取得的称重值 | 传输整数除以 10 为克；例如 1476 → 147.6 g |
| 28 | `night_mode` | 夜灯键相关模式状态 | 按实体键时 MQTT 即时切换 0/1 |
| 30 | `bottle_list` | 已登记奶瓶的列表页 | 17 字节：1 字节页号 + 8 个大端 UInt16 重量；每槽具体缩放应以对照为准 |
| 31 | `night_light` | 夜灯状态 | 本次实体键对照中保持不变，和 DP 28 区分 |

其他 DP（0–2、5–6、8–12、14–17、19–20、23–24、29）的完整厂商字段名和枚举没有保存在当前工作区。不要根据索引、字段位宽或相邻功能自行起字段名。DP 30 列表页和 DP 27 当次重量是不同数据：前者是已登记槽位，后者是本次标记操作的读数。

### 编码布局（当前 MQTT 解码器所实现）

观察到的设备上报 body 以固定标记和数据点掩码组织：
- 外层帧起始字节为 `00 00 00 03`，随后为 MQTT 风格的变长长度。
- body 开头包含标志、命令 `0x0093`、4 字节序列号和动作 `0x14`。
- 接下来 4 字节大端掩码指示本帧携带哪些 DP；掩码之后先读 DP 0–14 的紧凑位字段，再读 DP 15–31 的定长字节字段。
- 解码必须按掩码中索引顺序和产品位宽前进，不能把所有 DPs 当成固定字节或假设单个字段独立成包。
- 以上是当前代码能处理的 1271W 上报形状，不保证适用于 BOLOLO 的其他型号或固件。

## 3. MQTT 与自动备奶事件

当前工作代码实现的已验证订阅形态：
- Topic：`dev2app/{device_id}`。
- Broker 主机需由运行环境提供；本仓库不写入用户实例的 Broker、设备 ID、家庭 UID。
- TCP 1883，MQTT 3.1.1。用户名形态为 `2$<APP_ID>$<uid>`，密码是本次云端 access token。不要输出或提交实际 token、UID、设备 ID。
- 每次备奶用 `detect_status=1` 开始和 `detect_status=0` 结束配对。使用结束报告中的 `record` 水量；短暂等待最多 5 秒补齐紧随其后的水量数据。仅有水量或仅有结束包不够确认一次完整事件。
- 设备序列号为 0 的周期不能可靠地用序列号去重；断线或漏掉开始包时应标记需要人工补记。
- 代码证据：[feeding-web/bololo_events.py](../feeding-web/bololo_events.py)。

TCP 1883 当前未使用 TLS。若网络链路不可信，凭据可能被同链路观察；仅在受控网络使用，并避免将 Broker 端口暴露到互联网。不要在新的实现中默认为可公开暴露。

## 4. 已验证的 HTTP API（与 APK 静态解析分开）

这些端点来自客户端实现、云端响应或实机对照，不代表全部都直接从 APK 反编译字符串中获得。短信认证的完整请求包、错误码和图形验证码缺口见[认证流程文档](AUTHENTICATION.md)。

| 操作 | 请求 |
|---|---|
| 查询自有设备 | `GET /app/smartHome/v2/users/devices` |
| 查询共享设备 | `GET /app/smartHome/homes/shareDeviceListV2` |
| 查询 P50 状态 | `POST /bololo/app/device/status/{PRODUCT_KEY}/{MAC}`，`data={}` |
| 控制 P50 | `POST /bololo/app/device/control/{PRODUCT_KEY}/{MAC}`；称重验证使用 `bottle_tag` 及可选 `new_bottles` |
| 查询备奶历史 | `POST /bololo/appdataSata/foam/detail/{SNO}/3`；请求体格式、分页边界见[协议研究 §6.3](PROTOCOL_RESEARCH.md#63-读取-app-云端备奶历史) |

状态与控制 HTTPS 主机为 `app.bololoapp3.com`，统一响应需检查 HTTP 状态和业务 `code`，具体 JSON 包裹在认证流程及代码中有说明。

## 5. 已有硬件对照与限制

- App 执行奶瓶标记时，去皮阶段上报 DP 21 为 1；放入容器后上报 DP 27 新重量；状态随后回到 0。实测重量传输值为克的十分之一。
- OpenWrt 用获分享的设备权限可按 DP 21 顺序触发 `0 → 1 → 2`，读取去皮和新重量；不同负载得到 147.6 g、62.5 g 等与测试物相符的结果。
- 夜灯实体键改变 DP 28；短按可作为一次自动称重流程的触发信号。临时监听验证过：夜灯键触发去皮，用户放瓶后自动触发取重。
- 标记流程与已登记奶瓶列表有关。新候选编号不一定写入永久槽位；是否会占槽需同时比较 `new_bottles`、`bottle_list` 并在流程后复读确认。
- 当前已验证对照不能证明奶瓶喂前/喂后差值在长时间内完全准确，也不意味着设备提供待机实时托盘克重。实际喝入量只能由同一奶瓶、相同配件条件下的喂前/喂后重量差估算。
